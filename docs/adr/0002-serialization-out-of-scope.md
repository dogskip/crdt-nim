# 직렬화는 이 라이브러리의 범위 밖이다

CRDT 는 네트워크로 복제하기 위한 자료구조인데, 이 라이브러리는 인코딩과 디코딩을 제공하지 않는다. 병합 연산의 수렴 성질만 검증된 상태로 두고 전송 형식은 사용하는 쪽의 프로토콜(JSON, gRPC, 자체 이진 형식)에 맡긴다. 형식을 여기서 정하면 그 형식이 곧 호환성 약속이 되어, 값을 하나 더할 때마다 전송 호환을 깨지 않을 방법을 궁리해야 한다.

## 검토한 대안

- **JSON 인코딩 제공**: 바로 사용할 수 있지만 `NodeId`·`Timestamp`·`EntryId` 의 표현이 공개 API 가 되고, tombstone 집합처럼 큰 상태에는 비효율적이다.
- **이진 형식 제공**: 효율은 좋지만 형식 버전 관리와 언어 간 호환까지 책임져야 한다.
